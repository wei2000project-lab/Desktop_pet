# Nova 資料讀寫、儲存位置與格式調整計畫

日期：2026-10-08

狀態：第 1 階段已完成；第 2–5 階段尚未實作

## 目標與範圍

將可提交的程式預設資料、使用者設定、對話資料、可重建快取及憑證分開管理。使用者資料不再寫入 Git 工作區；模型與 Tavily 金鑰不再以明文欄位寫進 JSON／INI。所有讀寫路徑由單一介面決定，遷移時保留資料、處理中斷與重試，並能確認舊明文副本已清理。

本計畫涵蓋 `data/` 內的資料、專案根目錄的舊 `config/` 與 `.env`，以及同樣屬於執行時資料的 `logs/`。Tavily 與 DuckDuckGo 的搜尋選擇、網路請求行為不在本次變更範圍。

## 現況與待解問題

目前 `data/config/app.defaults.ini`、`data/config/prompt.json` 和 `data/app_control/aliases.json` 是 Git 追蹤的預設資料。其他資料平放在 Git 忽略的 `data/runtime/`；記錄寫在專案根目錄的 `logs/`。這能防止一般 `git add` 將目前的 runtime 檔案加入，但無法防止強制加入、複製到其他位置，或在專案外分享明文檔案。

| 現有資料 | 用途 | 目前問題 |
| --- | --- | --- |
| `app.ini`、`prompt.json` | 一般設定、人格覆寫 | 與私密資料、快取共用目錄 |
| `api_groups.json` | 模型群組與金鑰 | `key` 欄位是明文 |
| `api.ini` | 舊版模型設定與金鑰 | 與群組金鑰重複；群組模式仍保留舊檔 |
| `tools.json` | Tavily 等工具設定 | `tavily_api_key` 是明文 |
| `history.json`、`memory.json` | 對話與長期記憶 | 含私人內容，與快取共用目錄 |
| `preferences.json` | App 使用偏好 | 持久資料與可重建索引共用目錄 |
| `apps.json` | 本機 App 掃描索引 | 可重建資料與持久設定共用目錄 |

現有讀寫分散在 `ConfigManager`、`AppIndex`、`AppPreferenceStore` 與 logger；`tools.json` 的位置甚至由 `app.ini` 路徑換檔名推得。啟動時的舊資料遷移會保留 `config/` 原檔，其中 `config/config.ini`、`config/prompt.json` 目前未受 `.gitignore` 保護。這些檔案在本工作區不存在，但舊安裝可能仍有。

## 目標位置

保留 Git 追蹤的唯讀預設資料；Windows 使用者資料移至 `%LOCALAPPDATA%/NovaDesktopPet/`。開發與測試透過可注入的路徑提供者改用暫存目錄，不以修改全域路徑或寫回專案模擬。若使用者資料根目錄無法取得或建立，明確回報錯誤，不退回專案目錄。

```text
專案/data/
  config/app.defaults.ini       # 隨程式提供；唯讀
  config/prompt.json            # 隨程式提供；唯讀
  app_control/aliases.json      # 隨程式提供；唯讀

%LOCALAPPDATA%/NovaDesktopPet/
  settings/app.ini
  settings/prompt.json
  settings/api_groups.json
  settings/tools.json
  state/history.json
  state/memory.json
  state/preferences.json
  cache/apps.json
  logs/app.log
  migration/state.json          # 不含金鑰；記錄版本與已完成步驟

Windows 使用者憑證保管機制
  模型 API Key（依 group ID、key ID 對應）
  Tavily API Key
```

整個新資料根目錄在 Git 工作區之外。遷移期間仍保留 `data/runtime/` 的忽略規則，並補齊舊 `config/` 的忽略規則。`cache/apps.json` 缺失時重新掃描；設定、偏好、歷史與記憶不得因讀取失敗而當作空白資料覆寫。

## 資料格式與讀取語義

1. **模型群組：**`api_groups.json` 的 schema 從 v1 升至 v2。保留群組 ID、名稱、URL、模型、順位與啟用狀態；儲存型金鑰改為 `source: "credential"` 與不含秘密的 `credential_ref`，移除 `key` 欄位。`environment` 來源仍只保存環境變數名稱；免金鑰模式不建立憑證。讀取 v1 僅供一次性遷移，正式執行只接受 v2。
2. **工具設定：**`tools.json` 升至 v2，Tavily 設定保存 `credential_ref` 與非秘密選項，不保存 `tavily_api_key`。保留現有其他工具欄位，對未知欄位採明確的版本化相容規則，避免套用設定時無聲刪除。
3. **舊 API 設定：**`api.ini` 只作遷移來源，不再作正式設定或金鑰後備來源。完成遷移後，不再因群組檔缺失而重新從舊檔復活已刪除的金鑰。
4. **一般設定與人格：**`app.ini`、`prompt.json` 的內容格式先保持不變。讀取順序為專案預設值，再疊加使用者設定；寫入只針對使用者位置。
5. **對話、偏好、快取：**`history.json`、`memory.json`、`preferences.json` 的內容格式先保持不變，僅移動位置並補上格式驗證。`apps.json` 可直接重建，不需把舊索引當成重要資料遷移。
6. **設定畫面：**已儲存金鑰只回傳「已設定／來源／可更換」狀態，不把原文重新載入輸入框。空白輸入代表不變更；另設明確的更換與清除操作。新輸入在套用前只留在當次編輯狀態，錯誤訊息、`repr`、日誌與測試輸出不含秘密。

憑證存取由單一 `SecretStore` 介面負責，提供讀取、建立或更新、刪除與可用性檢查。設定檔只存不透明參照，不存金鑰、金鑰片段或可還原的編碼值。Windows 憑證保管方式在實作階段以可測試的介面封裝；若憑證服務不可用，停止該項設定的儲存或請求並給出明確錯誤，不把金鑰改寫為明文。現有 `OPENAI_API_KEY` 環境來源繼續支援，但不複製其值進設定檔。

## 讀寫責任與一致性

新增集中路徑提供者，清楚區分「程式預設」、「使用者設定」、「持久狀態」、「快取」、「日誌」；`ConfigManager`、App 控制與 logger 都從它取得路徑。各資料類別有明確的讀取與保存介面，不再由另一個檔案的位置推算路徑。

保留設定批次儲存的驗證與失敗回滾，但將「更新憑證」和「寫入參照檔」設為可恢復的兩階段流程：先建立憑證、驗證可讀，再原子寫入不含秘密的設定檔；失敗時撤銷新憑證或保留舊設定可用。成功後才清理被替換的舊憑證。檔案寫入使用同目錄暫存檔與取代；歷史、記憶、偏好也採相同方式，避免程式中斷留下半份 JSON。記錄檔只能寫事件、路徑類別及安全錯誤碼，不寫金鑰、完整請求、完整對話或含秘密的物件表示。

## 遷移與回復

遷移來源包含現有 `data/runtime/`、舊 `config/`，以及可能存在的專案根目錄 `.env`。先做唯讀盤點與格式驗證，目的地已存在時不覆寫，衝突要回報並保留兩邊資料。明文 `.env` 中只有程式認得的金鑰可列入匯入；其他變數不得擅自刪除或改寫。

1. 以測試專用假憑證庫先驗證 v1→v2 與路徑映射，再用臨時使用者資料目錄演練完整流程。
2. 正式遷移先建立憑證並驗證可讀；寫入新格式與不含秘密的進度標記。遷移步驟需可重入，重新啟動不得重複建立金鑰或覆蓋較新的設定。
3. 透過正式讀取介面重新讀取新資料，比對所有非秘密欄位、資料筆數和金鑰可用性；不在日誌記錄金鑰或其雜湊。
4. 驗證前一律保留原檔。驗證完成後清理舊明文 `api.ini`、v1 `api_groups.json`、舊 `tools.json` 中的金鑰副本，以及能安全判定為已轉移的 `.env` 金鑰。其他舊檔要有明確清理清單；不能承諾一般刪檔可抹除磁碟、同步服務或既有備份中的歷史副本。
5. 遷移失敗時保持舊資料原狀、停止切換到新格式，並提供重試與診斷資訊。若新版本需要回退，優先回退程式並恢復遷移前的資料備份；含秘密的備份只放在工作區外並由使用者帳戶保護，不加入 Git。

新程式啟動時先檢查新位置及遷移狀態。遷移成功後只讀新位置；不再默默回退到舊 `data/runtime/`，避免使用者已刪除的金鑰或對話重新出現。新資料版本高於程式支援版本時拒絕覆寫。

## 實施順序

| 階段 | 工作 | 完成條件 |
| --- | --- | --- |
| 1. 路徑與資料清單 | 建立路徑提供者、檔案分類、讀寫契約及 `.gitignore` 防線 | 所有執行時寫入點可列舉；測試可指定暫存根目錄 |
| 2. 非秘密資料 | 移動一般設定、人格、歷史、記憶、偏好、索引及日誌；補原子寫入和格式驗證 | 預設值疊加及現有功能正常；資料損毀不被空檔覆蓋 |
| 3. 憑證與格式 | 實作 `SecretStore`、API 群組 v2、工具設定 v2、畫面「保留／更換／清除」語義 | 新設定檔沒有金鑰原文；請求仍取得正確憑證 |
| 4. 遷移與清理 | 遷移 `data/runtime/` 與舊 `config/`，處理重試、衝突、備份及舊副本清理 | 中斷後可重試；驗證成功才移除舊明文副本 |
| 5. 驗收 | 回歸測試、實際桌面啟動、Git 與秘密掃描、備份還原演練 | 下列驗收條件全部達成 |

## 驗收條件

- 新安裝與升級安裝均不在專案內新增使用者資料或金鑰；原有 `data/runtime/` 與舊 `config/` 只在遷移期間作來源。
- 新版 `api_groups.json`、`tools.json`、INI、日誌及 Git 追蹤檔案中沒有可讀金鑰；設定畫面預設不回填已存金鑰原文。
- 模型群組切換、環境變數來源、Tavily 金鑰套用／更換／清除、對話歷史、記憶、App 偏好與重新掃描均通過功能驗證；不以目前的 Tavily 搜尋故障作為儲存遷移的成功條件。
- 測試涵蓋缺檔、損毀檔、目的地衝突、憑證服務失敗、檔案寫入失敗、遷移中斷與再次啟動；任何失敗都不丟失或覆寫原資料。
- `git status`、`git ls-files`、`git check-ignore` 與秘密掃描確認保護範圍；舊版副本清理後再做一次檔案盤點。

第 1 階段的讀寫清單見 `docs/data-storage-inventory-2026-10-08.md`。目前僅集中路徑定義與補強 Git 忽略規則；尚未對現有 runtime 資料、憑證或檔案格式執行遷移。
