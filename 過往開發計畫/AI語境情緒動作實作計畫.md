## 1. 目標與範圍

讓 Nova 在產生 AI 回覆時，依對話語境決定適合的表情，再由程式以採用機率決定是否顯示。沿用現有文字串流與動畫系統，不為情緒判斷額外發送一次 AI 請求。

本次將情緒圖片與播放規則放在 `app/animation/`，維持資料契約、對話串接、動畫邏輯與畫面顯示的責任分離。

不修改 Tavily 遺留功能、API 金鑰切換策略或歷史資料格式；不在此階段擴充設定視窗。`rate` 先提供設定檔參數，日後可透過既有三層架構增加設定介面。

## 2. 已確認規格

### 2.1 情緒與素材

實際目錄為 `assets/pet/emotions/`，不是 `assest/pet/emotion/`。已確認目錄中的 `Nova_gaze.png` 改名為 `Nova_squint.png`。

| 識別名稱 | 素材 | 使用語境 |
| --- | --- | --- |
| `happy` | `Nova_happy.png` | Nova 表達開心、稱讚或慶祝 |
| `surprised` | `Nova_surprised.png` | Nova 對意外情況感到驚訝 |
| `squint` | `Nova_squint.png` | Nova 懷疑、半信半疑 |
| `none` | 不切換圖片 | 語境無須使用情緒，或無合適情緒 |
| `idle` | `Nova_idle.png` | 預設狀態；不列入 AI 情緒候選 |

判斷的是 Nova 回覆時適合呈現的情緒，不能只因使用者提到「開心」「懷疑」等字詞就觸發。避免在引用、否定或嚴肅安慰的語境下錯配表情。

目前素材是靜態 PNG；此階段以停留圖片實作，不將它們當成多幀動畫。

### 2.2 採用與優先順序

使用者所稱「其他動作」，專指 emotions 目錄中除 idle 以外的情緒。

1. AI 每則回覆最多提供一個情緒選擇：`happy / surprised / squint / none`。
2. 僅當選到合法的非 idle 情緒時，執行一次機率判斷。
3. 採用時立即終止當前動畫，顯示選定情緒；不等待原動畫播完，也不在情緒結束後續播被中止的幀。
4. 選擇 `none`、標記無效或機率未命中時，不發出動作切換，不中斷動畫，也不主動改成 idle。
5. 「不介入」不等於凍結畫面：原動畫照原本流程播放、結束或自然回到 idle。
6. 不得為提高變化而隨機改選另一種情緒。重複選到目前情緒且通過抽樣時，可更新本次情緒的生命週期，不需先閃回 idle。

### 2.3 機率與時間

- `rate` 預設為 `0.3`，合法範圍為有限數值 `0.0～1.0`。
- 意義是「AI 建議使用情緒時，有 30% 機率採用」，不是保證每十則對話出現三次。
- 每則回覆最多抽樣一次，不能每個串流片段重抽。
- `rate = 0` 永不採用；`rate = 1` 對合法且有素材的情緒必定採用。
- 回覆開頭辨識到情緒且採用後立即顯示；回覆期間保持，完成後再保留 3 秒，接著回 idle。
- 情緒期間暫停隨機眨眼、左右看與閱讀排程，避免它們覆蓋表情。

- 目前動畫結束會回 idle；新增情緒後須防止舊動畫 tick、閱讀排程或舊情緒到期回呼覆蓋新表情。

## 4. 架構與資料流

```text
對話語境 + 情緒提示規則
    → 同一次 AI 回覆：情緒標記 + 正文
    → 每請求獨立的串流解析器
        ├─ 純文字 → 現有對話框／歷史紀錄
        └─ 情緒候選 + request ID → 情緒採用邏輯（rate）
                                      ├─ 不採用：無動作
                                      └─ 採用：Animator 終止舊動畫並顯示情緒
    → 該請求完成 → 保留 3 秒 → idle
```

責任劃分：

- **契約**：定義情緒名稱與帶 request ID 的事件資料，不依賴 Qt 或檔案系統。
- **AI 串接**：加入提示、解析輸出、過濾標記與排除過期請求，不控制圖片或計時器。
- **情緒邏輯**：白名單、素材映射、rate 驗證與一次性採用判斷；可注入亂數來源以便確定性測試。
- **Animator**：在主執行緒控制中斷、顯示與到期；以目前情緒的 request ID／世代辨識有效回呼。
- **UI**：只接收純文字與圖片，不判斷語境或抽機率。

## 5. 輸出協定與串流處理

建議使用回覆開頭的保留標記，例如：

```text
[[emotion:happy]]
太好了，你完成了！
```

這是本功能的程式協定，不是對使用者顯示的文字。AI 只可輸出白名單名稱，不得輸出檔案路徑、程式碼或任意動作命令。

解析要求：

1. 每個 request 建立自己的解析狀態；支援標記在任意位置被切成多個 chunk。
2. 僅解析正文前的第一個控制標記；正文中的引用或相似字串不能再次觸發情緒。
3. 前綴緩衝設固定長度上限，不因缺少結尾而無限等待或吞掉整份回覆。
4. 沒有標記的正常回覆照常顯示，視為 `none`；無效控制前綴採保守處理，丟棄可辨識的控制區段並保留其後正文，不觸發情緒。
5. 明確辨識為控制標記但在完成時仍不完整的片段不顯示；一般文字不得被誤當控制資訊丟棄。
6. 串流與非串流 fallback 使用同一套解析規則，不能在完成回呼再次抽樣或重複顯示正文。
7. 歷史儲存與 `ai_message_finished` 使用相同的清理後正文，避免畫面與歷史內容不一致。
8. 標記違規不得導致整則回答失敗，不因格式錯誤自動重發 AI 請求。

標記協定可在實作時依測試結果微調，但上述一次性、有限緩衝與正文保留原則不變。

## 6. 生命週期與例外處理

以下為實作預設，補足正常完成以外的邊界：

| 情況 | 處理 |
| --- | --- |
| 合法候選但機率未命中 | 不停止任何動畫，不更動既有情緒到期時間 |
| 新請求開始 | 更新活動時間與請求識別，不單憑開始事件切圖片 |
| 新請求採用情緒 | 取代舊狀態，舊計時器／完成事件不能覆蓋新情緒 |
| 該情緒所屬請求完成 | 從完成時起計算 3 秒 |
| 該請求取消或失敗，且情緒已顯示 | 視為結束，保留 3 秒後回 idle，避免永久停留 |
| 請求取消或失敗，尚未採用情緒 | 不介入動畫 |
| 舊請求的延遲片段或完成事件 | 忽略，不能改圖或重新設定新情緒期限 |
| 情緒素材缺失或不可用 | 在中止當前動畫之前驗證，失敗則不切換 |
| 非聊天互動或明確播放要求 | 保留既有操作語意；若取代情緒，須撤銷舊情緒的到期回呼 |
| 應用程式關閉 | 停止本功能計時器，不留下可影響已銷毀物件的回呼 |

聊天相關活動不應繼續共用會強制回 idle 的路徑；開啟設定、拖曳等原有非聊天操作則另行保持既有規則。

## 8. 分階段執行

### 第一步：契約、採用規則與設定

- 建立情緒契約、白名單及素材映射，確認 squint 對應懷疑。
- 加入預設 rate，缺值／非法值回退 0.3，拒絕 NaN、無窮大與超出範圍的值。
- 建立可注入亂數的純判斷，先驗證 rate 邊界、none 與非法情緒。
- 驗收：沒有 Qt 視窗也能測試判斷；此階段尚不接入正式對話。

### 第二步：輸出協定與解析器

- 在系統提示加入一次性情緒選擇規則。
- 完成串流前綴解析、無標記兼容、有限緩衝與清理後正文。
- 驗收：逐字拆 chunk、整包非串流、無效／截斷標記與正文引用均有測試。

### 第三步：對話串接

- 每個請求使用獨立解析器，將純正文送到現有 UI 與歷史保存路徑。
- 情緒候選與結束事件攜帶 request ID；延續現有取消與舊回覆檢查。
- 驗收：一則回覆最多一次候選，不增加 HTTP 次數，歷史不含控制標記。

### 第四步：動畫中斷與期限管理

- 接入採用規則；採用前確認素材可用，採用後立即停止動畫與閱讀計時器。
- 加入情緒狀態、所屬請求識別與完成後 3 秒單次計時器。
- 分離聊天活動記錄與動畫中斷，處理新情緒取代、取消／錯誤及舊回呼。
- 驗收：不採用時原動畫可繼續逐幀播放；採用時立即切換且不被舊 tick 覆蓋。

### 第五步：整合驗證與文件收尾

- 使用假 AI 回覆、固定亂數與可控計時驗證完整流程，不以真實 API 當自動測試前提。
- 執行相關測試後跑完整 unittest 套件，確認設定三層架構與既有聊天功能不受影響。
- 視覺確認 happy／surprised／squint、情緒持續時間與正常動畫恢復；真人語境抽查與自動測試結果分開記錄。
- 更新本文件實作紀錄與限制，核對 diff 與資料檔，依使用者指示進行本地提交。

## 10. 後續可擴充項目

未來可增加設定視窗上的採用機率控制、更多表情或多幀情緒動畫。新增設定時沿用 UI／串接／邏輯三層，不讓 UI 直接讀設定檔或執行抽樣。
